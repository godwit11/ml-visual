> 本篇记录「AI 助教 Nya」从后端逻辑到可交互面板的完整落地过程，含实测数据与踩坑复盘。

## 一、这一轮做了什么

给站点加了一个**机器学习教育助教**，名字叫 Nya。它不是一个通用聊天机器人，而是**知道自己正在被哪一页的哪一组数字问着**的助教。

学生打开任意演示页，右下角有一个「问 Nya」的按钮。点开后可以直接问「我这个 MSE 算好吗」——她能看到你此刻屏幕上的斜率、截距和四个指标的真实数值，于是能指着屏幕回答，而不是背一段百科。

**交付清单**

| 文件 | 作用 |
|---|---|
| `chat/nya.ts` | Nya 的人设 + 服务端知识表 + 提示词组装 |
| `chat/handler.ts` | 核心逻辑 `handleChat(Request): Response` |
| `api/chat.ts` | Vercel 入口（一行转发） |
| `src/core/nya.ts` | **前端面板**（浮动按钮 + 对话） |
| `src/styles/chat.css` | 面板样式 |
| `scripts/tests/nya-panel.js` | 面板回归断言（25 项，不消耗额度） |
| `scripts/nya-smoke.mjs` | 真模型冒烟测试（需密钥，不进口归） |
| `tsconfig.server.json` | 服务端独立类型检查 |
| `.env.example` | 环境变量模板（不含密钥） |

## 二、三个设计决定（都不是随手定的）

### 1. 密钥绝不能进前端 —— 唯一可行路径是「加一层代理」

站点是公开的。网页发给浏览器的任何东西，按 F12 都能看到。所以密钥一旦写进前端 JS，等于把充值卡贴在店门口。

> **不记名类比**：API key 像一张不记名的充值卡。谁拿着它，谁就能刷你的额度。
> 它必须藏在一个浏览器看不到的地方。

于是产生了这条链路：

```
浏览器  →  自己的代理接口 /api/chat  →  MiniMax API
                    ↑
             密钥存在这一层，永不下发
```

代理就是 **Vercel 的 Serverless Function**（在项目里放一个 `api/chat.ts`，Vercel 自动把它变成一个网址）。不需要买服务器、不需要运维，密钥填在 Vercel 后台的环境变量里 —— 一块只有服务器读得到、浏览器读不到的存储区。

**代价（如实说）**：项目从「纯静态站」变成「静态站 + 一个接口」，部署稍复杂一点。

### 2. 知识放服务端，前端只能上报白名单键名

前端不发送任何「事实」，只发送一组**键名在服务端白名单里的状态值**（如 `mse = 84.42`）。
「这一页讲什么」「有哪些术语」「最优解是多少」全部由服务端查表给出。

**这是防提示词注入的第一道闸**：如果允许前端随便塞一段文本进提示词，等于把系统提示词的控制权交给了浏览器。

### 3. 用真实数字防幻觉 —— 上下文同时是「让回答更有用」和「防止乱说」的手段

站点的立站原则是「页面上每个数字都要能追溯到某次真实运行」。助教当然也不能例外。

所以把页面的真实状态作为**唯一可靠事实来源**写进提示词，并明确禁止她在这些数字之外编造任何数据。

实测有效。问「这个数据集里房价的平均值是多少」，她的回答是：

> 「平均值我没在数字里看到。不过你想想：截距 b 是房间数为 0 时的预测值，那平均房价会显示在哪儿？」

**「我没在数字里看到」** —— 正是这套设计要的效果。

## 三、两个真坑（都值得单独记一笔）

### 坑 1：40% 的请求返回空回答 —— 根因是「思考 token 也计入输出上限」

**现象**：连续 5 次同样的请求，**失败 2 次**。返回 `EMPTY_REPLY`，模型的 `content` 字段是空的。

**根因**：MiniMax-M3 默认开启「自适应思考」（adaptive thinking）。虽然用 `reasoning_split` 可以把思考内容分到单独字段、不混进正文，但——

> **思考消耗的 token 仍然计入 `max_completion_tokens`。**

当时上限设 600，模型一思考就把额度烧光，**正文一个字都没输出就被截断**，`finish_reason` 是 `"length"`。

**修法**：关掉思考。但参数值文档没写全，所以**没有猜，直接实测**：

| `thinking.type` | HTTP | 正文字数 | 思考 tokens | 耗时 |
|---|---|---|---|---|
| 不传（默认 adaptive） | 200 | 395 | **71** | 1.8s |
| **`disabled`** | **200 ✅** | 213 | **0** | **1.2s** |
| `none` | 400 报错 | — | — | — |
| `off` | 400 报错 | — | — | — |

`disabled` 是有效值（`none` / `off` 都是错的）。**修复后复测 8/8 全部成功，0 失败。**

**顺带得到的教训**：间歇性 bug 必须**连跑多次**才能定性。单次成功或失败全凭运气，一次测试说明不了任何事。

### 坑 2：CSS 层叠 —— ID 选择器把 `pointer-events: none` 悄悄压掉了

面板容器是一个铺满视口的固定层，本身不吃点击（否则会挡住整页的文字选择），只有子元素吃：

```css
#nya { pointer-events: none; }
#nya > * { pointer-events: auto; }   /* ← 问题在这 */
```

而面板打开后要收起浮动按钮：

```css
.nya-fab[aria-expanded="true"] { visibility: hidden; pointer-events: none; }
```

线上表现「看起来是对的」—— 按钮确实看不见了。但它的 `pointer-events` 仍然是 `auto`：**`#nya > *` 里的 `#nya` 是 ID 选择器，权重压过了「类 + 属性」的组合**，那句 `none` 从来没生效过。

**是被断言抓出来的**，不是看出来的：

```
"打开后按钮已收起（不可见且不可点）": {
  "visibility": "hidden",
  "pointerEvents": "auto"      ← 这里
}
```

修法是用类选择器打底（`.nya-fab, .nya-panel { pointer-events: auto }`），让权重回到同一量级，谁更具体谁生效。

**另外把 `opacity: 0` 换成了 `visibility: hidden`**：只降透明度的话，元素依然留在无障碍树里、也依然能被 Tab 聚焦到 —— 「看不见却按得着」，用键盘的人会莫名其妙。

## 四、面板的两个结构选择

### 1. 状态由各页自己注册，面板不认识任何页面

```ts
provideNyaState(() => ({ w: fit.w.toFixed(2), mse: m2.toFixed(2), /* ... */ }))
```

面板只调用这个函数，不知道页面内部有 `fit`、`points` 这些变量。**加新页时只改那一页，面板一行都不用动。**

同理，演示页 id 从 **URL** 解析，不要求页面自报 —— 少一处可能写错的地方。之前 clustering 页漏掉 9 个 head 标签，就是逐页手抄漏的。

### 2. 测试用「假后端」，不真的调用模型

`scripts/tests/nya-panel.js` 在测试期间**把 `window.fetch` 换成一个假后端**。三个理由：

1. **确定性** —— 真后端每次回答都不一样，断言必然产生假失败，而**假失败会训练人忽略这个脚本**，比没有测试更糟。
2. **不烧额度** —— `vite preview` 也会挂上那段中间件、也会读 `.env.local`，真发一次请求就是真花一次钱；全量回归要跑很多遍。
3. **能测到平时测不出的分支** —— 「服务未配置（503）」「网络中断」这两个分支，只有在后端真坏了的时候才自然出现；假后端可以随时造出来。

这个脚本覆盖 25 项断言，其中包括**「AI 是增强项，不是地基」**这条设计承诺的验证：后端出错后，面板要显示提示、输入框仍然可用、页面其余功能不受影响。

## 六、已知限制（别当成已解决）

| 限制 | 说明 |
|---|---|
| **限流是尽力而为** | Vercel 函数无状态，计数只在单实例内有效，冷启动清空、多实例绕过。挡得住「手贱连点」，挡不住分布式刷量。要可靠得上 KV 或 Vercel WAF。 |
| **没做流式输出** | 第一版刻意选一次性返回（稳优先）。代价是等待期间只有「正在想…」动画，没有逐字效果。 |
| **只有线性回归页接了知识** | 其余 9 页会落到通用提示词 —— 能回答概念问题、被明确要求不许提任何具体数字，但不能指着屏幕说话。 |
| **离线模式不可用** | 打包成手机 App 后（Capacitor），AI 助手必然失效。这是物理限制，绕不过 —— 所以它被设计成增强项而非必需项。 |
| **「直接告诉我」的遵从度** | 按要求她应当切换为正面解释，实测会先答半句再继续引导。不算 bug（教学上合理），但可以调。 |

