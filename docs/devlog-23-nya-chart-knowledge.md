# devlog-23：让 Nya 说准「S 形曲线在哪」（方案 A + B）

> 2026-09-16。用户报的问题在 devlog-22 之前就出现了，但一直没修：
> **她一口咬定主图上有条 S 形曲线，而学生只看到一条虚线。**

## 1. 用户报的原话与我们的第一轮结论

> 「nya 在聊天过程中一直说有 s 线，但是我只看到了虚线」

上一轮（诊断轮）已经查清她的三处错误：

| 她说 | 实际 |
|---|---|
| 「虚线是概率 0.1 和 0.9 的两个边界」 | 页面上**没有等概率线**，那是「参考最优」 |
| 「主图背景里那条 S 形曲线」 | 主图背景是**概率色块**，没有曲线 |
| 「权重和截距都是 0，所以它退化成一条平直的 0.5 横线」 | **实测不成立**，曲线形状不变，变的是轴窗口 |

以及一个更根本的发现（见 `MEMORY-details.md` §13）：

- 页面初始状态 `w₁=w₂=b=0`，这时**主图上「当前边界」根本画不出来**，
  画面里**唯一的线就是那条橙色虚线** ⇒ 学生看到的"虚线"就是它；
- **S 形图在页面下方**（y=817，视口高 903）⇒ 不滚下去看不到；
- 而且此刻那条曲线**是直的**（z 窗口被 `Math.max(0.6, 跨度×0.12)` 兜底成 ±0.6）。

## 2. 根因：两个缺口，正好一个在提示词、一个在知识表

**缺口一（A）：没有任何地方告诉她「你看不到图形」。**

「不要猜这一页显示了什么图表」这句话**只写在兜底分支里**
（那一页没有知识表时才生效）。**有知识表的十页反而没有这条约束** ——
于是她以为自己对这些页了如指掌，开始描述外观。

**缺口二（B）：这一页的知识在"位置"上是模糊甚至误导的。**

```ts
what: '…分数越高越可能是 B 类，中间那条 S 形曲线就是分界。'
                                              ↑ "中间那条"
facts: ['…手动拖一下 S 形曲线会跟着动…']
                              ↑ 但没说它在哪张图
```

三张图分别在**上方、下方左、下方右**，没有任何一处写着"S 形曲线在下方的哪一张"。
她手里只有一个"中间那条"，于是自行找了个位置。

## 3. 改了什么

### A：`header` 里加一节通用约束（对十页都生效）

```
# 你能看到什么、看不到什么（重要）

**你能看到的只有数字** …… **你看不到任何图形**

所以学生问「在哪」「长什么样」时：
- ✅ 说**位置和名字**
- ❌ 不要描述它此刻的样子（直/弯、什么颜色、什么形状）
- ❌ 不要断言哪条线此刻可见
- ❌ 不要在图上「认领」一个东西
- 连位置也不确定时：说「我不确定它在哪儿，你在页面上找找看」

**宁可说不知道，也不要编一个图形出来。**
```

放在 header（而不是只给这一页）的理由：**这个错误模式在十页都会出现** ——
决策树的切分线、聚类的簇边界、PCA 的方差图，都会被她"描述外观"。

### B：知识表加 `charts` 字段 + 这一页的页面构成

```ts
charts?: { title: string; what: string }[]
```

它和 `facts` 分开，是因为两者角色不同：
- `facts` 是**结论**（"月牙那组是线性模型的天花板"）
- `charts` 是**位置索引**（"S 形曲线在下方右边那张图里"）—— 学生能拿着它去屏幕上核对

提示词里渲染成一节 `## 这一页的图（学生问「XX 在哪」时，从这里找）`，
header 里那条约束直接指向它，两者必须对得上。

同时修掉 `what` 里那句 **「中间那条 S 形曲线」** ⇒ 改成「sigmoid 那条曲线就是分界」
（那句话本身就是误导的来源），并补了三条 facts：

- 学生说的「S 形曲线」= 下方右边那张图里的青绿色线，**上方大图里没有曲线**；
- 那条线**形状会随参数变**（参数全 0 时接近直线，拖大权重才显出 S 形）；
- **权重全为 0 时「当前边界」画不出来** ⇒ 这时大图上只剩那条橙色虚线。

## 4. 实测（真模型，问三个问题）

用导出后的真实提示词直接打 MiniMax（`nya:prompt` → 拼 messages → 上游）。

**第二问是诈她的** —— 故意把她原来的错话说成前提：

```
学生：s线在哪里？
Nya ：页面下方右边那张图里，横轴是 z、纵轴是概率，那条青绿色的线就是 S 形曲线。

学生：主图背景里那条 S 形曲线是干什么的？        ← 诱导
Nya ：上面那张大图的背景不是 S 形曲线，是一片概率色块 —— 每个位置按预测概率上色，
      越红越偏向 B 类，越蓝越偏向 A 类。S 形曲线只在下方右边那张小图里。

学生：那为什么我有时候看不到它弯？
Nya ：因为权重全接近 0 的时候，横轴只展开很短一段，整条线挤在一小块，看起来几乎是直的。
```

**第 1、3 问全对，第 2 问顶住了诱导并主动纠正** —— 修好了。

### ⚠️ 但第二答暴露出一个残留：「越红越偏 B、越蓝越偏 A」是**编的**

实测配色是 `#6366f1`（紫）↔ `#0d9488`（青绿）之间插值，**跟红蓝没关系**。

原因很清楚：我给了她"背景是一片概率色块"，**却没说是什么颜色** ⇒ 她自己补了一个。
⇒ 在 `charts` 里补上真实配色（并说明它和散点/图例是同一套色）。

补完重测：「颜色越偏青绿，模型越觉得那里属于 B 类；越偏紫色，越觉得属于 A 类」✅

**教训**：**"说不知道"这类约束挡得住"编一整条线"，挡不住"编一个细节"** ——
只要知识点留了缺口，她就会用最省事的先验去填。
**补缺口比加禁止更有效。**

## 5. 顺带修掉一条「会误报的断言」

加完 `charts` 之后 `check:server` 红了一条：

```
❌ 没有 prev 时不出现变化清单  ← "不该有变化行"
```

判据是 `/^- .+：.+ → .+$/m`（匹配变化清单的行格式 `- 键：旧值 → 新值`）。
而新加的图表清单里有一行：

```
- **S 形映射：z → 概率（下方右边那张小图）**：横轴 z = w·x + b、纵轴概率。……
```

**页面上这张图的真实标题就带箭头** ⇒ 被当成了变化行。

这条判据已经**换过两次**：最早用「提示词里有没有 `→`」（教学策略那段
「学生仍困惑 → 把步子变细」会误报），改成行格式正则后又被图表清单误报。

⇒ 改用**结构性判据**：`!system.includes('学生动过这些')`
（那一节的标题只在 `diffLines` 非空时才拼进去）。

⚠️ **同时补了正向那一半**（`changed.system.includes('学生动过这些')`）——
没有它的话，"不出现"这条很可能是永远绿的空断言。

**反证做了**：把服务端改成 `diffLines.length >= 0`（恒真）⇒ 那条立刻变红，
且精确报出 `不该出现「学生动过这些」那一节`。

## 8. 补齐其余九页的 `charts`（2026-09-17）

原先只有逻辑回归一页有图表清单，这次把其余九页全部补上（连同首页共 11 页，首页无图）。

| 页 | 图数 | 容器 id |
|---|---|---|
| linear-regression | 1 | `chart` |
| model-evaluation | 4（+2 个非图元素） | `chart-dist` / `chart-roc` / `chart-pr` / `chart-cv` |
| svm | 2 | `chart-boundary` / `chart-alpha` |
| naive-bayes | 1 | `chart-odds` |
| ensemble-learning | 2 | `chart-boundary` / `chart-curve` |
| clustering | 2 | `chart-cluster` / `chart-inertia` |
| pca | 2 | `chart-space` / `chart-scree` |
| decision-tree | 1（+1 张手绘树） | `chart` |
| neural-network | 2 | `chart-space` / `chart-loss` |

**写法约定**（沿用逻辑回归那页）：
1. **位置**用学生能一眼对上的说法：「页面上方那张大图」「下方左边那张小图」；
2. **标题逐字照抄**页面上写着的那行字；
3. 轴名 + 每个 series 画什么，**颜色和线型也写**（学生会说「那条虚线是什么」）；
4. 🔴 **专门写清"什么情况下会看不到"** —— 这是这轮最值钱的部分。

### 三处「看不见」的坑（都**实测核实过**，不是照抄代码推断）

1. **linear-regression**：页面刚打开斜率是 0 ⇒「当前直线」是一条**水平线**（不是没画）。
2. **pca**：初始旋转角正好对齐 PC1 ⇒ 黑色虚线「你转的轴」**被红色实线压在底下**，
   看起来只有一条红线。实测两条线端点只差 **2px**（线宽 2~2.2px）⇒「看起来只有一条」成立。
3. **clustering**：点过「重置」之后 —— 轨迹虚线 **4 条 → 0 条**，
   inertia 曲线 **2 个点 → 1 个点**（一个点连不成线）。
   实测办法：点按钮前后对比 `getOption().series` 的数据点数。

### 成本

每页只带**自己那页**的清单（`chartSection` 取 `demo.charts`），所以提示词增长有限：

```

clustering           3562

```

## 9. 手机上拖不动她，还会上下滚页面（2026-09-17，**已修 —— 用户选了 B**）

**症状**：手机上想挪 Nya，她跟不动，页面却在上下滚。

**根因**（实测两端 `.nya-mascot` 的 `touch-action` 计算值）：

| | 桌面端 | 移动端 |
|---|---|---|
| 她的 `touch-action` | **`none`** | **`manipulation`** |
| 拖拽的 pointerdown 监听器 | 挂着 | **也挂着**（只排除了「面板已打开」） |

`touch-action: none` **只写在 `@media (min-width: 641px)` 里**（`chat.css` 第 601 行附近），
移动端没有 ⇒ 浏览器把触摸判定成**滚动手势** ⇒ 页面开始滚，
同时发出 `pointercancel` ⇒ `endDrag()` 结束拖拽
⇒ 表现就是「她跟不动 + 页面在滚」。

**这不是 bug，是当初的设计意图没做完整。** `chat.css` 的注释写着：

> 只在桌面端开（见文件末尾的媒体查询）：**手机上她是不可拖的**

但代码**没有真的禁掉拖拽** —— 只靠「移动端没设 `touch-action: none`」来"顺带"阻止。
结果是**最差的一种组合**：拖拽逻辑照样启动、`setPointerCapture` 照样抓、页面照样滚。

**用户选了 B**（原话是"不能像在电脑上一样流畅移动nya"，所以他要的是"能拖"）。
实施记录另立一份：**`docs/devlog-24-nya-mobile-drag.md`**。

- **A. 移动端真的禁掉**：符合原设计；代价是手机上不能挪她。
- **B. 移动端也允许拖**（用户选的）：和电脑一致；
  代价是她占的那块（右下角 116×116）**不能"起手就滚页面"**。
- **C. 长按约 300ms 才算拖**：既能滚又能拖；代价是多写约 20 行、且要"按住等一下"。
  ⇒ **留作后备**：若 B 的代价在实际使用中变得碍事，换成 C 是独立的一步，不用回头重做。
