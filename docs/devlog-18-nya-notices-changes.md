# 开发日志 18：Nya 看得见「你在哪一页 / 你改了什么」+ 面板可拖动

> 这一轮用户提了四件事（并批准了上一轮列出的 A/B/C 三个缺口）。
> 最有价值的部分**不是功能**，而是中间挖出来的一个 bug：
> 一个字段在服务端被静默丢掉，而**三道防线全都没拦住**。

---

## 一、四个需求

| # | 需求 | 做法 |
|---|---|---|
| A | 她能说出"你改了什么" | 前端记住**上一次成功送达**的快照，跟着每次提问一起发；服务端比对白名单键，把前后值并排列出 |
| B | 读复选框 | 读取器加了 `input[type=checkbox]` → `已打开 / 已关闭` |
| C | 读输入框文字 | 读取器加了 `textarea`，键名用 `aria-label`（朴素贝叶斯那个短信框本来就有） |
| D | 她在首页也知道你在首页 | 见下 |
| E | 把她缩小、落到对话框右上角 | `PERCH_INSET = 6`，趴着时 `height: clamp(92px, 8vw, 118px)` |
| F | 拖对话框上半部分能移动整个面板 | 抓手是**标题栏**，见下 |

### D：为什么 A/B/C **解决不了**首页

用户问「nya 看不到首页的内容，改完之后这个能解决吗」——**不能**，得单独做。
首页是唯一一个**没有指标卡**的页面：没有滑杆、没有数字，通用读取器在那里
什么都取不到（这一点没错，首页本来就没有可读的量）。

真正的毛病是**她连"你在首页"都不知道**：`currentDemoId()` 只认 `demos/xxx/`，
首页返回 `undefined` → 落到兜底分支。所以用户会看到
「看不到，我只能看到你发的文字。你现在方便告诉我是哪一页吗?」

修法：
- `currentPageId()` 认得站点根 ⇒ 返回 `'home'`；
- 给首页也写一条知识表（分成哪五组、每组讲什么、首页没有数字）；
- 首页额外上报两个键：`已看过的页数`、`看过的页`（来自 `getVisited()`）。

复测：**「你在「首页」—— 就是那个分成五组的目录页。已看过的页数 = 2 / 10，看过的是线性回归和模型评估。」** ✅

### E/F：两处用户没说透、但必须替他决定的地方

**E**：趴着时"要小一圈"，因为面板是 380×540 而这张立绘横向铺开接近身高的 1.7 倍 ——
按待机尺寸趴上去，整只猫占了面板上头一大块，**面板反倒成了她的配角**。
待机时她是独立的东西，那个尺寸是对的，所以只改趴着那一套。

**F**：用户说"拖动对话框的上半部分"。**我做成标题栏，并且要说明为什么** ——
面板上半部分里是消息列表，那是要能**选中文字、能上下滚**的区域；
把拖拽挂上去，想选一段话就会把面板拖走，手机上连滑动浏览都会被吃掉。
标题栏是整块面板里唯一"没有别的用途"的地方。
（想扩大抓手范围的话告诉我扩到哪块。）

拖动还有三件事要同时成立，缺一样就读起来像坏了：
1. **她必须跟着走** —— 她是"趴"在面板上的，面板走了她留在原地就穿帮。
   所以拖拽期间给猫娘加 `.is-dragging`（关掉那 460ms 过渡），否则面板跟手、她在后面追。
2. **拖到哪儿就记到哪儿**（`savePos()`），刷新页面她还在那儿。
3. **松手那一下的 click 要吞掉** —— 否则"我想挪一下面板"会变成"面板被关掉"
   （松手的位置可能正好压在关闭按钮上）。用捕获阶段的 click 拦。

## 二、🔴 本轮的真正教训：一个字段被静默丢掉，三道防线全没拦住

加 A 的时候，我给请求体加了 `prev`（上一次快照）。改完之后测 Nya 的回答：

```
第一次问"我刚在页面上动了什么？"
→ 「你刚刚动了「判定阈值」那个滑杆 —— 往上拖了。…所以召回率会掉」
```

**看起来完全正确** —— 于是我差点就收工了。但同一份提示词连问两次，第二次变成
「我看不到你刚才动了什么」——**同一份输入两次相反的结论**，这不合常理，才继续挖。

先怀疑模型不照办 → 写了一版更强的指令（把变化值重复进结尾那条硬指令、给一句可照抄的开场句）
→ 还是不行。于是把**提示词打出来看**，一切正常。再往下查才发现：

**`handler.ts` 的 `normalizeContext()` 是"白名单式拷贝"，我忘了往里加 `prev` 这一行。**

它被丢掉之后：
- **类型检查过** —— `prev` 是可选字段，不传也合法
- **前端断言过** —— 请求体里确实带着 `prev`
- **提示词"看着也对"** —— 我的调试脚本直接调 `buildSystemPrompt`，**绕过了 handler**

而那条"第一次的正确回答"其实是**她猜的**：从"阈值 0.79 且召回率 0.544"反推出
"你多半是拖了阈值"。**一个碰巧对上的答案，比一个错的答案更危险。**

### 补上的防线

`scripts/check-server-path.mjs`（进 `verify:all`，不起浏览器、不花钱、结果确定）
走**完整链路**：`Request → handleChat → normalizeContext → 组装 → 上游 payload`，
把上游 `fetch` 拦掉（省钱 + 能看完整 payload），然后断言 14 项，包括：

- `prev` 里的值必须出现在提示词里（这条就是回归用例）
- 变化清单里必须列出跟着变的指标
- 结尾硬指令里必须重复一遍具体值（近因）
- 两份快照相同时**不能**说成"你没有上一份状态"
- 没有 `prev` 时不能出现变化清单

> 教训一句话：**"提示词看着对"不等于"上游收到了"。**
> 调试脚本必须走完整链路，不能直接调中间那个纯函数。

## 三、顺带发现的两件事

### 1. 采样温度一直没设，是默认值 1

MiniMax 文档：`temperature` 默认 **1**，范围 [0,2]（中文版文档写 (0,1]）。
我们从来没传过 —— 于是**同一份提示词两次结果不同**（上面那次"两次相反"，
不全是 prev 丢失的锅，温度也在里面）。

对一个**要守规矩**的助教来说，"每次说法不一样"本身就是缺陷。
现在显式设 **0.3**（取两边文档都合法的区间，留一点变化避免句式完全雷同）。

### 2. 我自己写的提示词自相矛盾

「有快照但没变化」这一支，正文说"你手上有上一份状态，而且它和现在一模一样"，
而结尾那条最高优先级指令（`changeReminder`）却**落进了"没有快照"的分支**，
说的是"你手上没有可比对的上一份状态"。模型听的是结尾那条 ⇒ 答成"我看不到"。

修法：把三态（`changed` / `same` / `none`）在**正文和结尾指令两处保持一致**。
这个自相矛盾是"把提示词打出来逐行读"才发现的 —— 光看她的回答只会一直在改措辞。
