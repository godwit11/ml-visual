# devlog-20 · 用一段视频换掉「趴在对话框上的 Nya」

> 用户给了一段自己生成的视频（864×496 @ 24fps，4.1s），要求用它里面的素材
> 替换掉现有趴在对话框右上角的 Nya，并**保持动作连贯**。
>
> 结果：`src/assets/nya-twitch.webp`（33 帧动图）+ `nya.webp`（静态首帧）已替换，
> 位置/尺寸逻辑一行没改（`PERCH_OVERLAP=4` / `PERCH_INSET=6` 照旧），
> 面板断言 64/64 ×2 视口全绿。
>
> 但这条路踩了**四个坑**，其中两个是"看起来完全正常、只有量化才发现"的，
> 都值得记住。

---

## 1. 先摸清这段视频在讲什么

**没有 ffmpeg、没有 Python 视频库** ⇒ 抽帧交给浏览器（见 §2）。

- 帧率与帧号用 `requestVideoFrameCallback` 问出来：**97 帧 @ 24fps**。
- 动作轨迹（把 36 帧铺成 6×6 接触表 + 逐帧差分量化）：

  | 时间 | 内容 |
  |---|---|
  | 0 ~ 3.2s | **抬头微笑**，只有轻微起伏 |
  | 3.2 ~ 3.4s | **快速低头**（帧间差 ~90） |
  | 3.4 ~ 4.1s | 一直低头（帧间差 ~26） |

- 抬头段里有一段**周期约 0.683s 的微动**（呼吸 + 1~2px 的整体位移）。
  而 **2.048s 正好是它的 3 倍** ⇒ 第 0 帧和第 49 帧几乎是同一个姿势
  （实测首尾差 6~9，只有自然微动的 1/3）⇒ **天生可以无缝循环**。
- 所以循环段 = **第 0~48 帧**。低头那一段不能进循环（会一顿）。

⚠️ **先量再切**。若不做这个分析，直接拿整段 4.1s 循环，接缝处会有一次明显的一顿。

## 2. 抽帧：浏览器 + 网格截图（三个坑）

链路：`scripts/extract-video-grid.js` 把帧裁好、按 1:1 画进 3×3 网格 →
e2e driver 截图落盘 → `scripts/prepare_nya_perch_video.py` 切网格。

### 坑 1：截图尺寸有限制
4×4（2908×1720）和 5×5（3635×2150）都会让 `Page.captureScreenshot` **直接超时**。
**3×3（2181×1290/1488）是稳的** ⇒ 49 帧分 6 批。

### 坑 2 🔴 `seeked` 事件 ≠ 画面已经画出来
第一版 `await onseeked` + 等 25ms 就 `drawImage`，
结果 **49 帧里有 26 帧画的是空白**，而且呈**固定周期**（每格里第 3、6~9 格必坏）。

修法（现在脚本里的做法）：
1. `await` 一次 **`requestVideoFrameCallback`**（它会等到"真的有一帧被呈现"）；
2. 画完之后**自检这一格**（数还剩多少底色像素）；
3. 不合格就等 120ms 重画，最多 8 次；
4. 返回值里带上每格的自检结果。

⚠️ **画布底色要用醒目的洋红**，不要用黑色 ——
空白格在 #000 底上看起来"就像正常的深色画面"，肉眼根本分辨不出来。
（第一版就是黑底，于是坏帧一路混进了下游。）

### 坑 3 🔴 窗口尺寸 ≠ 视口尺寸
`--size 2181,1488` 的窗口，**实测视口只有 2147×1391**
（浏览器边框/滚动条吃掉了 34×97）。画布 2181×1488 超出视口 ⇒
截图只截到视口那一块 ⇒ Python 侧切网格切到越界，PIL **补黑**。

表现是"一列 + 一行整片是黑的"。当时误判成"抽帧失败"，
**在抠图算法上白绕了很久**（还以为是"尾巴一帧有一帧没有"）。

修法：脚本里**硬校验** `innerWidth/innerHeight ≥ 画布尺寸`，
不满足就直接返回 `{ok:false, reason:...}`。跑的时候窗口开大一点（`--size 2320,1660`）。

## 3. 抠图：虚化背景是真难

背景是**虚化的咖啡馆灯光**（不是纯色）⇒ `prepare_nya_perch.py` 那套
"按亮度吃白底"完全用不上。改用**以描边为墙的区域生长**：

1. 颜色梯度（三通道取最大）当墙，墙**膨胀 2px** 封住描边上的小缺口；
2. 从画面四边区域生长 ⇒ 可达的算背景；
3. 剩下的算她 ⇒ 填洞（被围住的是她内部）→ 只留最大连通块 → 收壳 2px。

### 三个必须记住的约束

**① 必须喂整幅帧（高度 496），裁图要放到抠完之后。**
区域生长是从四边播种的。第一版先裁掉下半部分（y 0~430），
裁剪框下边界正好切在她身上 ⇒ **洪水从她身体内部起步，把她从里到外吃穿**（脸上缺一大块）。

**② 裁剪线那一行要加"围栏"。**
她搭在板子上的手那条边界本来就难分，`wall[CROP_Y:CROP_Y+6, :] = True`
横着封死，下面那半幅随便它怎么长（围栏自己会被裁掉）。

**③ 虚化背景的软边会超过阈值，形成"假墙"。**
背景的梯度 p90 就有 29（她轮廓带 p90 也才 36）——**两者根本分不开**。
假墙会把一片背景围起来，`fill_holes` 于是把它填成"她"。

### 🔴 尾巴那一段：试了四种办法，最后靠"裁剪"解掉

她的**尾巴在摆**（从卷曲的"S"形摆到近乎竖直）。尾巴和头发之间有一块**亮光斑**，
于是那一带时而被围住（填成她）、时而露出来（正常吃掉）：
**尾巴区像素 13864 → 4489 → 10541**，动图里就是一闪一闪。

试过、都不够：
- 阈值扫描（th 22/26/30/35 × 膨胀 2/3/4）：面积波动一直 12~16%，没有一档明显更好；
- **所有帧共用一份轮廓**：能把闪消掉，但**会把尾巴的摆动一起冻住** ——
  而尾巴的摆动正是这段动画里最明显、最该保留的动作（用户明确要求"保持动作连贯"）；
- 定点种子（把"多数帧是背景、少数帧是她"的像素判成背景）：
  **会把尾巴一起啃掉** —— 尾巴扫过的地方，多数帧里确实没有尾巴；
- 逐帧颜色门控种子（只在"这一帧它确实像背景"的像素上撒）：修不掉，
  因为那块光斑在**后段帧里被摆过来的尾巴盖住**，同一位置前段是背景、后段是她。

⇒ **最终决定：横向裁一刀（`CROP_X = 560`），把尾巴裁掉。**
整个不可靠区域直接落在画面外。裁剪区内面积波动立刻从 **13.5% → 1.6%**。

代价：没有尾巴了，构图从"她 + 尾巴"变成"她探头"（资产 292×236，原来 519×300）。
那一刀落在她右侧发梢上，看起来像"人像被裁到边"。
**想要尾巴的话，让视频改用纯色/透明背景重出一版，抠图会立刻退回简单问题。**

## 4. 成品与验收

| 项 | 值 |
|---|---|
| `nya-twitch.webp` | 292×236，33 帧（49 帧去重后）@ 16.2fps，**375 KB** |
| `nya.webp`（静态首帧） | 292×236，无损，68 KB |
| 循环时长 | 2.04s（保持原视频总时长不变） |
| 接缝 | 末帧→首帧差 8.3（自然微动约 26） |

- **尺寸依据**：趴着时她的显示高度是 `clamp(92px, 8vw, 118px)`
  （`chat.css`，**不是**待机的 124~160）⇒ 2 倍图只需 **236px**，
  比按 150px 算省掉三分之一体积。
- **质量取舍**：`quality=72, alpha_quality=35`（旧素材是 82/60，但那张画得简单）。
  483px 宽时 33 帧要 785KB，236px 高时 459KB（含尾巴时）。在 118px 的显示高度上看不出差别。
- `npm run e2e:nya` / `e2e:nya:mobile`：**64/64 全绿**（几何断言都是相对量：
  重叠 4px、右距 6px、高度比、不压关闭按钮 ⇒ 换尺寸不会挂）。
- 真实页面实测：立绘 `292x236` 已加载、重叠 `4`、右距 `6` ✔
- **深色主题下效果很好**；浅色主题下偏淡 —— 这是**新画本身的配色**
  （旧画有很重的深色描边，新画线条更细更浅），不是抠图问题。
  想改善就给她加一点 `filter: drop-shadow(...)`（透明底 ⇒ 阴影会跟着轮廓走）。
