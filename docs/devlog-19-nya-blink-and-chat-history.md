## 一、眨眼：几何压扁**不可行**，只能合成

### 先说我否掉的方案，因为它是"看起来最自然"的那个

直觉做法：把眼睛纵向压扁成一条闭眼线。数据是：眼睛高 61px（成品图 519×300 里），
要压到 ~8px 才有"闭"的观感 ⇒ 腾出 **~52px** 的竖直空间，必须由周围的皮肤/刘海
**被拉伸**来补。

按"向闭合线 L 收缩"定义位移场后，映射在 q 处的一阶导是

```
1 + amount · ( w(q) + (q−L)·w'(q) )
```

衰减区里 `w' < 0` 而 `(q−L)` 又大 ⇒ **必然变号 ⇒ 映射折叠**（实测在离闭合线
~37px 处折叠）。要让导数恒正，衰减宽度得 ≥ **52px** —— 那等于把整张脸都卷进来。

**结论：闭眼不能用几何压扁做。** 这一步有实测（合成测试图上红方块被压成"沙漏"，
竖网格线扇形收敛）。

### 最终做法：合成一只闭眼

只动眼框内部，外面一个像素不碰：

1. **逐列求「刘海下沿」** = 区域顶往下第一个亮像素。**那条线以上原样保留** ——
   刘海被平切是肉眼最敏感的破绽。
   ⚠️ 要给它一个下限（22% 眼高）：右眼有一列的"第一个亮像素"探到 y=219
   （那是**横跨眼睛的细发丝**，整列都是暗的），不限住的话那一列什么都不替换，
   闭眼后留一条没闭上的缝。
2. 以下用**三段色调锚点**铺皮肤，都是实测值：
   - `眼皮` = 刘海下沿那几行的真实皮肤（上眼皮被刘海压着，本来就暗）
   - `眼侧` = 眼框左右外侧的皮肤（浅白，眼周主色调）
   - `眼下` = 眼下那一行做**横向滑动平均**（抹掉腮红斜线 ⇒ 不再有竖条纹）
   左右两列再朝"同行最近的皮肤色"渐变靠 ⇒ 补丁边界消失。
3. **闭眼线 = 原图上睫毛的暗核心**逐列提取 → 滑动平均 → **二次拟合**成一条光滑弧
   → 内眼角一侧收细。好处是形状和颜色天然和原画一致，不是我们"画"出来的。

### 中间帧：**不能交叉淡化**

第一版用 `Image.blend(睁, 闭, α)` 做过渡帧 —— 冻结看是**两层眼睛的鬼影**。
改成把"遮盖多少"参数化：眼睑从刘海下沿**逐级下压**，线以上铺皮肤、线上画闭眼线、
线以下保留原画的瞳孔 ⇒ 中间帧是真的半闭眼。

⚠️ 只压上眼睑不够：到 85% 时瞳孔下半还露在闭眼线下面（看起来像半睁）。
所以 c ≥ 0.6 之后让遮盖面**向下延展**（下眼睑一起抬上来）。

### 🔴 我连错两个数学公式

二次拟合 `c ≈ a0 + a1·dx + a2·dx²`：

| 版本 | 错法 | 后果 |
|---|---|---|
| 第 1 版 | 把 a1 / a2 的公式**写反** | 线性项被当成二次项，拟合出振幅 50px 的大抛物线（闭眼线画成一坨黑影） |
| 第 2 版 | 照搬 "2×2 的 Cramer 公式"，**漏了先减均值** | a2 大一个量级，线跑到 y=516 |

正确形式（消去 a0 后）：

```
s11·a1 + s12·a2            = t0
s12·a1 + (s22 − s11²/n)·a2 = t1 − s11·mean_c
```

并加了 `LASH_MAX_CURVE` 兜底：拟合出的弧最多偏离均值 7px。
**教训**：拟合这种东西不该"凭记忆写公式" —— 先在一组已知数据上验算一次。

### 另一个坐标系 bug

`draw_lash` 里我把**原图坐标的 y** 当成**补丁局部下标**用（223 vs 补丁高 73），
循环体一次都没执行 —— 闭眼线根本没画上，而外面的图看着"只是眼睛没了"，
**不是黑屏、不是报错**。改完才画出来。

### 结果

`nya-twitch.webp` 从 142 KB 涨到 **180 KB**（29 帧 / 7.4s 循环）：
两次甩耳（0.9s 左、3.6s 右）+ 两次眨眼（2.05s、5.30s，240ms 一次）**故意不对称**
（等间隔会读成节拍器）。静态帧 `nya.webp` 仍是睁眼，供「减少动态效果」的用户。

## 二、对话记录跨页保留

### 根因

站点是**多页**应用：从线性回归点进 PCA 是一次真实的整页加载，JS 内存里的一切都会重来。
第一版把记录放在闭包里 ⇒ 一换页就没了。

### 修法

存在 `sessionStorage`（`nya:chat`），挂载时铺回消息列表。

**为什么是 sessionStorage 而不是 localStorage**：
sessionStorage 只在**同一个标签页**内跨页有效，关掉标签页就清空 —— 这正好是
"同一段学习过程"的边界；localStorage 会一直留在机器上（多人共用一台电脑时，
下一个人能看到上一个人问过什么），也可能几个月后突然"接上一段陌生的对话"。

配套：

- **清空按钮**（标题栏，文字而不是图标 —— 挨着关闭按钮，两个图标容易点错，
  而这个动作不可撤销）；请求进行中禁用。
- 有记录时**不再显示开场引导**（已经聊过了还显示"我是 Nya"，像失忆）；
  她的提示气泡也从「有不懂的问我」换成「**上次的对话还在**」。
- **学生那条消息立刻落盘**：万一请求没回来（断网/超时），换页后至少还看得到问过什么。
- 条数上限 40，读取时逐条校验类型（存储区可能是别的版本写的）。
- 提示词里补了一段：**对话历史可能跨页**，历史里的数字属于当时的页面，
  和现在的「真实状态」对不上时**以现在的为准**。

### 🔴 顺带查出：拖完之后"吞掉一次点击"的标志会一直挂着

实现里为了防止"挪一下她/面板"变成"打开对话/关面板"，会在拖拽结束时设一个标志，
让紧随其后的那次 click 被吞掉。**真实浏览器**会在松手后自动补一次 click 把它消费掉 ——
但如果指针被取消（`pointercancel`）或松手落在元素外，**那次 click 不会来**，
标志就一直挂着，下一次真实点击被白白吃掉（表现是"点她没反应"／"点清空没反应"，
`且极难复现`）。

⇒ 改成**会自己过期的标志**（400ms 超时兜底）：该吞的照吞，没人来消费时也会自己放下。

> 这个 bug 是写回归测试时撞出来的：测试用的合成事件不会产生浏览器那次自动 click，
> 于是"点清空没反应"稳定复现。**真实用户遇到的是同一件事，只是要碰运气。**

```
npm run typecheck   → 0 错误
npm run build       → ✓（退出码 0）

```

- 面板断言 **52 → 63 项**，四种视口（默认 / 1440×900 / 430×900 / 1024×700）**全绿**。
  新增的 11 条里，跨页那 6 条是这么验的：往 sessionStorage 里塞一段记录，
  再开一个**同源 iframe 指向另一页**（同源 iframe 会**复制**父页面的 sessionStorage，
  正好就是换页时的情形），检查记录被铺回来、开场引导没出现。
- **十页状态键对账 / 服务端链路 14 项** 依旧全绿。
- 安全检查：前端产物无密钥、无系统提示词。

### ⚠️ 构建这一步：`verify:release` 在本回合第二次构建时被护栏拦下

报的是 `SAFE_DELETE_BULK_CONFIRM_REQUIRED … count=311 threshold=50 scope=turn` ——
**沙箱的批量删除护栏按"回合累计"计数**，而 `vite build` 清空 `dist` 一次就删掉 300+ 个文件。
所以同一回合里**第一次构建会过、第二次会被拦**。

处置：不绕过护栏，改为**证明现有 `dist` 就是当前源码构建的**
（grep 本轮新代码的标志 + 校验 86 个 HTML 引用全部存在 + 退出码 0 的构建日志），
然后直接跑 `verify:all`（它本身不构建）。
