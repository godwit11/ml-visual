# ML 演示站 · 开发日志 11：降维技术（PCA）

> 第 9 个演示页。这一页最有意思的地方在于：PCA 的数学（特征分解）其实不难，
> 难的是**"该不该标准化"**这个看起来像工程细节、实际决定结论的问题。
> 本轮的对拍一次通过，但 e2e 抓出了一个"把教学点整个抹掉"的默认值 bug。

---

## 1. 这一页在讲什么

朴素的说法：**找一根轴，让数据在它上面的投影尽量散开。**

找到第一根（PC1），再在"与它垂直"的方向里找最散的（PC2），依此类推。
数据敢丢维度，是因为它常常**本来就没占满整个空间**——
鸢尾花有四个特征（萼片长/宽、花瓣长/宽），但第一主成分一个人就吃掉 **92.46%** 的方差，
因为这四个数基本都在描述同一件事：**这朵花有多大**。

教学切入点做成**"用手拖轴找方向"**：
旋转角滑杆控制一根虚线轴，旁边实时显示"当前投影方差"，
和 PCA 给出的 PC1 方差并排对照。拖到对齐那一刻，两个数字重合成 100.00%——
这就是 PCA 的定义，不需要先讲特征值。

## 2. 实现：零线性代数依赖

`src/algorithms/pca.ts` 全部手写，没有引用任何线代库：

1. **中心化**（减均值，**不除标准差**）
2. 对 `XcᵀXc/(n-1)` 用**对称矩阵的 Jacobi 旋转**做特征分解 → 得到主成分方向 `V`
3. 由 `Xc = U S Vᵀ` 回代出奇异值 `S` 与左奇异向量 `U`
4. 方差 = `sⱼ²/(n-1)`，解释方差比 = 该方差 / 总方差
5. 投影 `Z = Xc·Vᵀ`、逆变换 `X̂ = Z·V + mean`、重构误差

**为什么走 SVD 而不直接对协方差矩阵做特征分解？**
数学上等价，数值上不等价：先组协方差矩阵等于把奇异值**平方**了一遍
（σ → σ²），条件数从 κ 变成 κ²，最小那几根轴会丢精度甚至变负。
sklearn 默认走 SVD 也是这个理由。

## 3. 对拍：五个数据集，一次通过

对拍对象：`sklearn.decomposition.PCA(svd_solver='full')`。
5 个数据集 × 全维度 + 所有 k 的重构，逐项比对：

| 项目 | 最大偏差 |
|---|---|
| 均值 `mean_` | **0** |
| 主成分方向 `components_` | **2.4e-11** |
| 解释方差比 `explained_variance_ratio_` | **7.8e-16** |
| 投影坐标 `transform(X)` | **8.7e-11** |
| 重构 MSE | **6.9e-18** |

### 这轮对拍的两个特殊之处

**① 主成分的"符号"必须单独处理。**
特征向量 `v` 与 `-v` 是同一条直线的两个方向，两者都是合法答案。
numpy 与我的 Jacobi 实现取哪一侧完全是任意的，直接比数值会假报错。
正确做法是 `dot(a,b) < 0` 时翻转——比的是**子空间**，不是轴上的朝向。

**② 除了比数字，还要验"定义性质"。**
这轮额外验了两条：

- 主成分**两两正交**（`V·Vᵀ = I`）
- 投影之后**各列协方差为 0**（这就是"去掉相关性"的字面含义）

这两条比单纯比一堆数更能说明实现是对的——
数字可能碰巧对上，但轴不垂直就说明公式抄错了。

## 4. 两个反直觉的实测结论（写进页面 + 钉了断言）

### ① 标准化会把主成分整个换掉

鸢尾花标准化之后，PC1 从 **92.46%** 掉到 **72.96%**。
更狠的是我专门做的诊断实验（`scripts/diagnose_pca.mjs`）：

> 只把「萼片长」的单位从厘米换成 0.1 毫米（数值 ×100，**物理含义完全没变**），
> PC1 占比立刻飙到 **99.98%**，方向变成几乎只指着萼片长。

结论写成：**量纲不统一时必须标准化**（比如"收入（元）"和"年龄（岁）"）；
**量纲本来就统一时不要标准化**（比如四个都是厘米），
否则会把"哪个特征更重要"这个信息也一起抹掉。

### ② "解释方差比"和"重构误差"不是同一个尺度

标准化后 k=1 的方差占比更低（72.96% < 92.46%），
但重构 RMSE 反而**更高**（0.5182 vs 0.2926）。

一开始有点困惑，想清楚后是显然的：标准化把每一维的尺度拉到 1，
**误差的"尺"也跟着变了**——两个空间里的 MSE 不可比。

> ⇒ 跨数据集比较重构误差没有意义，只能在同一个预处理下比。

## 5. 从数据里挖出来的教学对照

页面的主线是两两对照，都是数据自己给出来的：

| 数据集 | PC1 : PC2 | 说明 |
|---|---|---|
| 相关二维（y ≈ 0.8x） | **98.29% : 1.71%** | 降成一维只丢 1.7%，**降维几乎白送** |
| 不相关二维 | **58.86% : 41.14%** | 降成一维必然丢四成，**没有冗余就没得压** |

这两组并排放着，就是"降维凭什么有效"最直白的答案。

另外三维点云降成二维保住 **99.42%**——这是"用二维图讲三维数据"的底气。
鸢尾花的完整代价谱：

| k | 保住方差 | 重构 RMSE |
|---|---|---|
| 1 | 92.462% | 0.2926 |
| 2 | 97.769% | 0.1592 |
| 3 | 99.479% | 0.0769 |
| 4 | 100% | 0 |

还加了一个更贴近实用的指标：**近邻保持率**（原始空间最近 5 个邻居，投影后还剩几个）。
鸢尾花降 4→2 保持 63.6%——比"保住 97.77% 的方差"更能反映结构有没有散架。

## 6. e2e 抓到的 bug

**切数据集时我写了 `k = Math.min(2, p)`。**

对 2 维数据集（相关/不相关那两组）这意味着**默认 k=2，等于根本没降维**，
页面上显示"保住 100%"——把这一页要演示的东西整个抹掉了。
断言"不相关数据降成一维要丢掉四成"失败，才逼出来。
改成 `max(1, min(2, p - 1))`。

**顺带修了个体验问题**：切数据集后旋转角还留着上一组的 0°，
指标卡显示一个突兀的 50%，看着像坏了。
改成切数据集/重置时默认对齐新的 PC1（`snapAngle()`），
"当前 = 最优 = 100%"立刻成立；想看没对齐的状态自己拖滑杆。

## 7. ⚠️ 顺手修掉一个存在已久的基础设施 bug

跑全量回归时发现异常：`npm run crosscheck:logistic` / `:eval` / `:svm` / `:nb` /
`:ens` / `:km` 全部报 `ModuleNotFoundError: No module named 'numpy'`，
而 `crosscheck` / `crosscheck:tree` 正常。

**根因**：这 7 个脚本把"读 `.venv-python` 切解释器"的逻辑写在了 `import numpy` 之后——

```python
import numpy as np           # ← 这一行就已经炸了
...
PY = sys.executable
cfg = ROOT / ".venv-python"  # ← 切换逻辑在下面，永远走不到
```

**import 早就执行了，切解释器再赋值一个变量根本不可能生效。**

为什么之前几轮没暴露：我一直是**直接调绝对路径**跑对拍的，
今天第一次用 `npm run` 串跑全套，才撞出来。

已用 `scripts/fix_crosscheck_bootstrap.py` 批量改成正确写法：

```python
def ensure_env():
    try:
        import numpy, sklearn
        return
    except ImportError:
        pass
    marker = ROOT / ".venv-python"
    if marker.exists():
        alt = marker.read_text(encoding="utf-8").strip()
        if alt and os.path.abspath(alt) != os.path.abspath(sys.executable):
            os.execv(alt, [alt, str(pathlib.Path(__file__).resolve()), *sys.argv[1:]])
    sys.exit(2)

ensure_env()        # ← 必须在所有 import 之前
```

**两条教训：**

1. 凡是"先 import 再判断环境"的脚本，都有"判断永不生效"的隐患。
   环境检查必须排在所有 import **之前**，并且用 `os.execv` **原地换进程**，
   而不是给一个变量赋值。
2. **回归要用用户实际会用的入口跑**（`npm run xxx`），不要图快直接调绝对路径——
   否则测的不是同一条路径，问题会一直藏着。
