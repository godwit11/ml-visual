# devlog-22 · 「报告问题」：一个贴右边缘的反馈入口

日期：2026-09-16
需求：用户想在每个页面的右下角放一个反馈系统 —— 有人发现错误时能直接发邮件给他。

---

## 1. 动手前的第一个发现：右下角不是空的

原话是"右下角"，但**右下角是 Nya 的地盘**：她默认落点在距右 24px / 距下 20px，
待机时占 214~277px 宽；面板打开时更宽（380px）。

所以先做了两个摆位的对比图（`靠边竖标签` vs `角落按钮 + 把她上移`），
让选择有依据。最后选的是**贴右边缘、竖直居中的竖标签**：

- 不占右下角 ⇒ 和她零冲突，将来她怎么拖都不影响；
- 反馈入口本来也不该抢眼（它不是主 CTA）；
- 代价是更低调、需要点一下展开 —— 可以接受。

---

## 2. 表单的核心不是输入框，是现场信息

用户报"这个数字不对"，可这一页有十来个数字、几十种参数组合。
**让他描述的成本很高，而附带的成本是零。**

站点里已经有一个现成的读取器：Nya 每轮对话上报的那份「页面状态」
（滑杆值、指标卡数字）。这次**没有重构它** —— 只加了一个读取出口：

```ts
// src/core/nya.ts
export function samplePageState(): Record<string, unknown> | undefined {
  return stateProvider?.()
}
```

零改动复用，而且因为读取器**每次重新读 DOM**，反馈表单拿到的是点击那一刻的值，
和"页面状态对账"那套测试盯着的完全是同一份实现。

附带还有：页面路径（**只用 pathname，不带 query/hash**）、视口、主题、UA、最近 5 条控制台报错。

**全部逐项列出来、逐项可取消**（默认全选）。采集这件事必须让人看得见 ——
做不到"坦白"，用户就会替你编一个不准确的描述。

### 控制台报错为什么必须捕获

装在 `feedback.ts` 的**模块顶层**（不是等面板打开再装 —— 那时候错已经发生过了）。
它是"页面白屏 / 图表崩了"这类问题**唯一**能拿到线索的地方：
用户只会说"打不开"，而堆栈只存在于控制台里。

⚠️ 有一条硬约束：`src/core/feedback.ts` 必须是**静态 import**（挂在 `chrome.ts` 上），
不能改成按需加载，否则页面开头那几秒的报错就漏了。

---

## 3. 送达：自建 `/api/report` + Resend

三条路摆出来对比过：

| 路线 | 密钥在哪 | 结论 |
|---|---|---|
| 自建接口 + 邮件服务（Resend） | **服务端** | ✅ 选它 |
| 自建接口 + 自己的邮箱 SMTP | 服务端 | 可行，但 Vercel 在海外连国内 SMTP 可能抖 |
| 第三方表单服务的公开 key | ❌ **前端源码里** | 省事，但等于把接口挂出去给人发垃圾 |

选的这条沿用 Nya 已有的规矩：**浏览器只知道自己提交了一份报告，永远拿不到密钥。**

Resend 的默认发件地址 `onboarding@resend.dev` 是给**未验证域名**账号的测试地址 ——
只能发到账号自己的注册邮箱，而"反馈发给自己"这个场景**刚好够用**。
⇒ **不验证域名也能立刻用起来**，验证之后换成 `feedback@godwit.asia` 更专业。

---

## 4. 防滥用：四层，缺一层邮箱就会被当垃圾桶

1. **蜜罐字段** —— 隐藏输入框（CSS 移出视口，不是 `display:none`，否则有些机器人会跳过）。
   填了 ⇒ **返回成功但什么都不做**，不给任何反馈。
2. **填写耗时** —— 打开到提交不足 1.5 秒基本是脚本。同样是静默丢弃。
3. **来源白名单** —— 挡住"别的网页盗用你的接口"（复用 Nya 那套）。
4. **IP 限流** —— 3 次/分钟。

⚠️ **限流的桶必须和 Nya 分开**：共用的话，学生问 Nya 十次之后就报不了问题了 ——
而"他刚问过 Nya 还是不懂，所以来报告"恰恰是最可能发生的情形。

---

## 5. 两个真实的安全点

### 5.1 邮件头注入

问题类型会进**邮件主题**。如果不过滤，`数字不对\r\nBcc: attacker@…` 就能伪造收件人。

**用白名单而不是"过滤掉换行"** —— 这里本来就只有 5 种类型，白名单更省心也更严。

### 5.2 `reply_to` 的地址校验

用户填的邮箱会进 `reply_to`（这样你点"回复"就能直接回给他）。
必须拦掉换行 + 用一个**保守**的格式检查；不合格就**当作没填**，
而不是报错（报错会让用户莫名其妙）。

这两条都有断言盯着：`scripts/check-report-path.mjs` 里那三条
"非法邮箱被丢掉"和"主题里绝不出现换行"。**反证验证过它们会红。**

---

## 6. 发不出去时，报告不能丢

```
没配密钥        → 503 + 如实告诉用户"通道还没开通"（**不假装成功**）
上游报错/超时   → 502 + 把**报告全文**写进服务端日志
```

"假装成功"是最坏的选择：用户以为问题报上去了，实际什么都没有。

## 7. 🔴 这一轮踩到的四个坑

### 7.1 部署形态检查有个盲区：它只验了一个入口

`check-vercel-bundle.mjs` 把入口**写死**成 `api/chat.ts` —— 编译是遍历所有文件的，
但**加载验证只 `import('./chat.js')` 一个**。

也就是说：新加的 `api/report.ts` 链路上任何一处写错（漏扩展名、引用了不存在
或被下划线前缀忽略的文件）**都不会被发现**，直到线上那个网址回 500。

改法：抽出一个 `ENTRYPOINTS = ['chat.ts', 'report.ts']` 列表，
**逐个编译 + 逐个 ESM 真加载**，并断言每个都导出了 `default.fetch`。

⚠️ 这个列表是**必须跟着加的**：以后再加 `/api` 下的入口，
漏了这一行就等于那个入口完全没有部署形态保护。

### 7.2 配色变量用错 —— 而**测试测不出这种错**

第一版把 `--primary-text` 配在 `--accent-weak` 底上（"发送"按钮）。
浅色主题下 `--primary-text` 是**白色**，而 `--accent-weak` 是近白底 ⇒
**白字落在白底上，"发送"两个字基本看不见**。截图里那个按钮像一块破损的图。

项目里成套的配对是：

- 实心按钮 = `background: var(--primary)` + `color: var(--primary-text)`
  （`--primary-text` 是"用在 primary 实心底上的字色"，**不是通用前景色**）
- 淡底强调 = `background: var(--accent-weak)` + `color: var(--accent)`

⇒ 这条教训值得单独记：**颜色配错不会报错、断言也测不到（它只是"不好看"），
只能靠眼睛看截图。** 所以"改完 UI 一定要截图看一眼"不是客气话。

### 7.3 层级太低：标签被 Nya 面板盖住一半

`.fb` 一开始设 `z-index: 50`（低于 `#nya` 的 60），理由是"让会动的那只在上"。

**这是错的。** 算一下就发现：Nya 面板宽 380px、默认落点会占到视口右侧
约 x 1014~1394，而竖标签在 1372~1406 —— **重叠 22px，超过它宽度的一半**。
表现是"标签点不到了"，而且**只在 Nya 面板打开时**出现。

改成 70 之后，用一个 `elementFromPoint` 断言把它钉住：
拿标签中心点问浏览器"这里是哪个元素"。反证时它给出的证据非常直接：

```
❌ Nya 面板打开时，反馈标签没被盖住   ← elementFromPoint 返回 "nya-chips"
（标签的位置上其实躺着 Nya 面板里的示例问题按钮）
```

### 7.4 测试的"偶发通过"比稳定失败更危险

有一条断言偶尔红、偶尔绿。我加了一行**无关的同步读**，它就绿了 —— 时序刚好错开。

真因：**提交成功后 2.2 秒面板会自动收起**，那个 `setTimeout` 还挂着，
在后续用例点击"重新打开"之后才到点，把刚打开的面板又关掉。

修法不是"多 sleep 一会儿"，而是**显式把待触发的定时器排干**（先等 2.4 秒），
让行为变确定；断言也改成先看同步的 `data-open`，再轮询可见性。

⇒ 判定标准：**连跑三次都绿才算数**（这条就是这么确认的）。

## 8. 环境坑：`verify:all` 不能和其他 e2e 并行

第一次跑回归时 SVM 那步红在：`驱动失败: DevTools 端口没起来`。
原因是我同时开了 dev server 和另一个截图用的无头浏览器 —— 端口撞了。

它导致的连锁反应很能骗人：首页断言数从 327 变成 **301**，
而 **301 = 327 − 26**，正好是 SVM 那 26 条没跑成。
看起来像"有人改了断言数没同步"，实际只是那一步没跑起来。

结论：**跑 `verify:all` 时不要并行任何会起浏览器的操作。**
（`pageAssertions` 的口径也值得记住：它**只统计演示页 + 首页/链接**那批，
`e2e:nya` / `e2e:feedback` 明确排除在外，见 `verify-all.mjs` 第 91 行的注释。）
