# 开发日志 17：Nya 能看见你在哪一页了 + 耳朵穿模的返工

> 这一轮的起因是用户的两条实测反馈，两条都指出我上一轮做错了。
> 记下来不是为了流水账，是因为里面有两个**下次还会踩的坑**：
> 「只有一页接入了知识」和「把耳朵切成图层」这两个决定，看起来都合理，实测都是错的。

---

## 一、问题一：她答的不是我看到的这一页

### 用户看到的现象

他在**模型评估**页问「那么在我看到的表格中是什么表现」，Nya 的回答是：

> 你现在在的这一页我看不见表格。你打开 **[线性回归]** 那一页，拖着 **样本数** 滑杆……

他再问「我现在是在模型评估页面你看不到吗」，她说「嗯，这一页我看不到」。

### 根因：不是 bug，是**只有一页接进来了**

`chat/nya.ts` 里的知识表 `DEMOS` 当时只有 `linear-regression` 一条。
其余九页落到兜底分支 —— 而那个兜底分支里写着一句我亲手写的话：

> 回答里可以建议他：「打开『线性回归』那一页，一边拖着滑杆一边问我」——
> 那一页是你唯一能看见屏幕状态的地方。

**她照办了。** 所以现象看起来像"她不认页面"，实际是"她只认识一页，而且被教成了每次都推那一页"。

### 修法一：十页全部接入

给每页写一句「这页解决什么」、术语表、硬事实、状态键白名单。
`facts` 全部来自页面自己的数据集定义与文案（可追溯），没有编造的数字。

### 修法二：状态读取改成**通用读取器**，不写十份

```
provideNyaStateFromPage()   // src/core/nya.ts
```

它读的是**页面上已经渲染出来的字**：

| 来源 | 取到什么 |
|---|---|
| `.metric`（`.metric-label` / `.metric-value`） | 「准确率 = 87.3%」 |
| `.ctrl`（`label` / `.ctrl-input`） | 「判定阈值 = 0.50」 |
| `select` + `label[for]` | 「数据集 = 稀有病筛查」 |

这三个容器是十页共用的版式（由 `makeMetric` / `mountSlider` 统一生成），
所以一个读取器覆盖全部页面，**加新页时不用改它**。

> 为什么不给十页各写一份：那正是"上一个/下一个"按钮当年写坏的老路
> —— 同一件事抄十份，改一处漏九处。这里宁可让读取器通用一点，
> 也不要十份会各自过期的代码。

两个刻意的细节：

- **每次调用重新读 DOM，不缓存**。拖完滑杆再问，报的必须是新值；
  报一个过期数字比不报更糟（学生会以为她在胡说）。
- **`-` 不算数**。指标卡还没算出来时显示 `-`，报了等于给她一个假数字。

### 修法三：兜底分支不再只推一页

兜底里那句"建议他去线性回归页"删掉了，改成从**全站页面清单**里挑最贴题的一页。
清单（10 个标题）现在每次都写进提示词 —— 学生问"该看哪一页"时她答得出来。

### 修法四：给这件事配一个会失败的检查

`scripts/check-nya-state.mjs` + `scripts/tests/probe-nya-state.js`。

**白名单最坏的失败方式是"不报错"**：页面上把「准确率」改成「判对率」，
Nya 就再也看不到这个数 —— 页面照常、测试全绿，只有学生问起来才发现。

所以这个脚本走**真实链路**核对：打开那一页、点开面板、真的发一次请求
（`fetch` 被换掉，不花钱），然后截下**请求体**，拿它和白名单对差集。

> 为什么不"在测试里把 DOM 读取逻辑再写一遍"：那等于把生产代码抄一遍，
> 抄错了测试反而会通过。截真实请求体才对得上。

第一次跑，它立刻抓到两页共 5 个键会被安静丢掉
（Logistic 页手写的「权重 w₁ / w₂ / 截距 b / 判定阈值」，
神经网络页动态生成的「第 N 个隐层的神经元数」）——
这些正是我之前用 grep 粗提文案时**漏掉**的控件。补进白名单后十页全绿。

## 二、问题二：耳朵穿模，出现两对耳朵

### 用户看到的现象

扒在窗口上沿时"出现了两对耳朵"，而且他要的不是"贴图整体转"，是**像动漫那样有层次感的抖动**。

### 根因（实测，不是猜）

有两个，叠在一起：

**① 呼吸动画只作用在身体图上，耳朵图层不跟着动。**

```
.nya-mascot[data-pos='perched'] .nya-mascot-img { animation: nya-idle 3.6s }  ← 身体
.nya-ear-l / .nya-ear-r                                                      ← 兄弟节点，不动
```

用 Web Animations API 把呼吸动画钉在 50% 相位量出来：

```
身体图框   1055.5, 786.4   279.8×165.3   （相对静止相位上移 8.6px）
左耳框     1097.0, 795.0    72.5×81.6    （纹丝不动）
```

差 8.6px —— 身体上原有的那只耳朵从图层后面露出来了，看起来就是"两对耳朵"。

**② 身体立绘上本来就有耳朵。**

耳朵图层是从身体图上原样裁下来的，图层转到一边时，**底下那只静止的耳朵必然露出来**。
即使把呼吸动画对齐了，只要旋转角度不为 0，就会穿模。

### 修法：不切图层了，改成对整张立绘做**局部网格形变**

耳朵的甩动现在是**烘焙进 `nya-twitch.webp`** 的：

- 每个像素按「沿耳轴走到哪、离轴多远」决定被旋转多少
- **耳根几乎不动、耳尖转得最多** ⇒ 耳朵是**弯**出去的，而不是被当贴纸转过去
- 旋转走开的区域由旁边的像素被"拉"过来补上：天空拉过来看不出来，
  头饰是平的也看不出来

于是**整幅画只有一只耳朵**，结构上不可能再穿模，也**没有任何接缝**。

### 三个踩出来的细节

**① 耳尖坐标必须手工量。**

裁剪框里混进了头顶的呆毛和脸侧的头发，所以"离支点最远的像素"会选到**呆毛**上
（实测选到身体图坐标 `(210,2)`），于是旋转轴整个偏掉 —— 甩起来呆毛在动、耳朵不动。
现在 `EAR_L_TIP` / `EAR_R_TIP` 是照着放大图手工读出来的。

**② 权重场会"逃逸"成一条无限长的胶囊。**

离轴半宽按耳轴收缩，但 `along/length > 1` 之后不再收缩，于是形成一条沿耳轴
无限延伸的胶囊 —— 实测一路伸到 `x=27`，比裁剪框还靠左 48px，**贴回矩形框不住它**。
现在越过耳尖一点点之后明确把权重掐掉，并实测确认：
权重场里"不透明且落在贴回矩形外"的像素是 **0**（切口全在透明区，看不见）。

**③ 耳根要留一段完全不动。**

沿耳轴的前 22% 权重为 0（那是埋在头发里的耳根）。不留这一段，耳朵会像被连根拔起。

### 体积与授权

```
nya-twitch.webp   141 KB   17 帧 / 5.60s（编码器把重复的静止帧合并成 15 帧）
nya.webp          112 KB   静止帧，给「减少动态效果」的用户
```

甩动时间线：左耳 1.0~1.5s、右耳 3.2~3.7s，5.6s 一轮。
**两只耳朵用同一条曲线但起始时间错开** ⇒ 不会同步抖（同步像机器）。

动图 WebP 是**浏览器层面**在播，CSS 停不掉它 —— 所以"减少动态效果"必须换静态图，
这条沿用待机动画的做法。

### 顺带修掉的：把测试的假失败挡掉

`nya-idle` 的呼吸动画有 460ms 的 left/top 过渡。Esc 之后固定等 450ms 量位置，
会踩在过渡的最后一点点上 —— 在 1406×1503 视口下**差 6px**，断言失败而界面完全正确。

这已经是这个文件里第二次"量在动画中间"的假失败（上一次是落座重叠量）。
所以不再猜时长，改成 `settle()`：**轮询到位移不再变化为止**。

## 三、验证

```
npm run typecheck   → 0 错误
npm run build       → ✓ 8.76s
npm run verify:all  → 31/31 步通过（新增「Nya 页面状态对账」）
```

- 面板断言 **桌面 39/39、移动 39/39**（把 5 条"耳朵图层"断言换成
  「不再有独立耳朵图层」+「扒窗口立绘是多帧动图」+「立绘已加载」）
- **十页状态键对账全绿**（这一步会打开全部 10 页并各发一次请求，不花钱）

### 真模型验收（`npm run nya:smoke`，会花一点额度）

先从一个真实页面截下状态喂进去：

```bash
node scripts/e2e.mjs --serve --url http://127.0.0.1:4173/demos/model-evaluation/ \
  --script scripts/tests/probe-nya-state.js          # → 16 个键
npm run nya:smoke -- --demo=model-evaluation --state=状态.json \
  --question="我屏幕上这个准确率算好吗？"
```

她的回答（节选）：

> 表里的准确率是 **64.3%**。算不算好，得看你怎么用……
> 你可以先看一眼正例占比是 **30%**……一个「啥都不干」的模型都能拿到 70%，
> 你现在的 64.3% 还不如它。

`64.3%` 和 `30%` 都只可能来自页面状态 —— 固定事实里没有这两个数。
「指着你的屏幕说话」这条核心能力，在**非试点页**上也确认成立了。

## 四、还没做的事

- **其余九页没有入门引导层**（`mountIntro` / `mountTerms` / `mountRecap`）。
  这一轮只补了 Nya 的知识表，页面本身的 A/B/D 层还是只有线性回归有。
- 面板会挡住页面的右侧栏。模型评估页的「当前表现」指标卡正好被面板压住 ——
  而 Nya 正在指着那几张卡说话。要么把面板默认落到左边，要么给她一个"让开"的位置。
- 模型评估页上同时存在两个叫"准确率"的量（主图 64.3%，交叉验证平均 93.15%），
  它们是不同模型/不同阈值下的结果。**这是页面本身的歧义**，Nya 也会被绕进去 ——
  实测她的回答里就把两个数并列了。建议给其中一个改个更具体的名字。
