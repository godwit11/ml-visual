# ML 演示站 · 开发日志 12：神经网络（MLP）

> 第 10 个、也是最后一个演示页。这一页和前面九页有一个根本区别：
> **它是有随机性的**。前九页跑出来的每个数字都是确定常数，这一页不是——
> 换一个种子就是另一个网络、另一条边界。
>
> 所以本轮的技术重心不是"把公式写对"，而是**怎么在随机性里做严格验证**。
> 顺便逮到一个教科书级的坑：无激活的多层网络，损失会稳稳下降，准确率却可能是 0%。

---

## 1. 这一页在讲什么

朴素的说法：**一层不够，是因为世界不是直的。**

单个神经元只能划一条直线（前面逻辑回归那一页已经讲透了）。
把很多个神经元叠起来、中间夹一个非线性函数，就能把直线"掰弯"成任意形状。
反向传播不是什么魔法，它就是**链式法则 + 一个聪明的计算顺序**。

这一页刻意只讲两件事，不贪多：

1. **决策边界怎么被掰弯的** —— 前向传播 + 激活函数的作用
2. **损失怎么降下来的** —— 反向传播 + mini-batch SGD

教学切入点做成**「无激活」当成一个可选的激活函数**。
切到它，不管把隐层加到多深多宽，异或的准确率都上不去（实测恒为 75%，
而且那个 75% 还是假象，见第 5 节）。这就是"非线性的来源是激活函数"，
一个可以亲手做的实验。

## 2. 实现：全部手写

`src/algorithms/neuralNetwork.ts`：

1. **前向**：逐层 `z = a·W + b`，`a' = f(z)`
2. **反向**：`δ_out = (p-y)/n`，`δ_l = (δ_{l+1}·W_{l+1}ᵀ)⊙f'(z_l)`，
   `dW_l = a_lᵀ·δ_{l+1}`，`db_l = Σδ_{l+1}`
3. **激活**：ReLU（0 处导数取 0）/ tanh / logistic / identity
4. **初始化**：Xavier/Glorot
5. **优化**：mini-batch SGD + 确定性 PRNG（`mulberry32`）洗牌

### 输出层的约定（对拍时确认过，容易搞错）

| 任务 | sklearn 的做法 | 我的做法 |
|---|---|---|
| 二分类 | **1 个 logit + sigmoid**（不是 softmax） | 同左 |
| 多分类 | K 个 logit + softmax | 同左 |

对拍验证：二分类强行套 softmax 会差 **0.467**，套 sigmoid 只差 **2.2e-16**。

### 交叉熵的漂亮结果

sigmoid 的导数 `p(1-p)` 刚好和交叉熵里的 `1/p` 项抵消，
最后输出层梯度只剩一个非常干净的形式：

```
δ_out = (p - y) / n
```

这个式子值得单独在页面上讲一遍——它是"为什么交叉熵配 sigmoid 是个好搭档"
的最直接答案。

## 3. 对拍：随机性算法怎么验

这是本轮最关键的方法论问题。**有随机性的算法不能直接比最终结果**，
因为两边随机初始化的权重根本不一样，跑出来必然不同。

拆成三条独立的验证线：

| 验证线 | 做法 | 结果 |
|---|---|---|
| **前向** | 把**同一份权重**塞给两边，只比 `predict_proba` | 最大偏差 **2.220e-16** |
| **反向** | 解析梯度 vs **数值梯度**（中心差分） | 10 组，最大相对误差 **4.480e-06** |
| **收敛** | 换不同种子各训一遍，看能不能达标 | 异或 **100%** |

反向检验用数值梯度是**独立验证**——它不依赖任何解析推导，
只要我的梯度写错了，数值梯度立刻拆穿。（除了第 4 节那个 bug，见下。）

数值梯度用中心差分：`(L(w+ε) - L(w-ε)) / (2ε)`。
最大误差 4.480e-06 出现在 sigmoid 饱和区，那里的绝对梯度只有 3.9e-6，
所以是"绝对量小导致的相对误差大"，不是实现问题。

## 4. ⚠️ 踩到的真 bug：梯度检验抓不到的那一类

训练日志是这样的：

```
损失 0.6931 → 0.0024   （降得非常漂亮）
准确率              0%   （全错，而且是"全预测反了"）
```

**损失一路下降，准确率却是 0%。**

根因：二分类的 `Y` 是 K 列 one-hot，但输出层只有 1 个 logit。
`backward()` 里本该取"原始标签"，却直接取了 `Y[i][0]`——
当 `y=1` 时 one-hot 是 `[0, 1]`，取第 0 列得到 `0`，
于是网络被训练成**输出反过来的**答案。损失当然在降（它在认真地拟合一个错目标），
准确率当然全错。

**为什么梯度检验没抓到？**
因为数学上它自洽——损失、梯度、更新公式全部互相一致，
只是**瞄错了目标**。数值梯度和解析梯度在这个错目标下依然高度吻合。

> 教训：**梯度检验只能验证"你算的梯度对不对"，不能验证"你算的是不是你想要的那个梯度"。**
> 前者是数学问题，后者是语义问题。要抓后者，只能靠端到端的行为断言
> （"准确率必须打上去"），或者一个独立的、从原始标签出发的参考实现。

修复：从 one-hot 反推原始标签。

```ts
const yi = Y[i][1] >= Y[i][0] ? 1 : 0
```

这个 bug 已经升级成页面上的教学点（原理第 ⑥ 节 + 思考题）。

## 5. 诊断：把反直觉的说法用数字砸实

这一页最容易变成"看图说话"——反正决策边界弯了就好看。
所以每个教学点都先量出来，页面文案只引用实测数字。

### ① 无激活 ⇒ 多层等于一层

| 结构 | 异或准确率 | 损失 | 概率跨度 |
|---|---|---|---|
| [2,2,1] identity | 75% | 0.693147 | 0.010 |
| [2,4,1] identity | 75% | 0.693147 | 0.007 |
| [2,8,1] identity | 75% | 0.693147 | 0.006 |
| [2,16,16,1] identity | 75% | 0.693147 | 0.007 |

损失**恒等于 ln2**（= 0.693147），概率跨度只有 0.006~0.010，
预测分布恒为 40:120。

**那个 75% 是假象。** 因为概率全部挤在 0.5 附近，
类别判定完全由浮点噪声决定，恰好蒙对 75%。这个坑差点被写进页面当教学结论,
后来加了 `probaSpread` / `predDist` 两个诊断量才拆穿。

### ② 有激活就没问题

| 结构 | ReLU 达标轮数 | tanh | logistic |
|---|---|---|---|
| [2,2,1] | 6 | — | 133 |
| [2,4,1] | 4 | — | — |
| [2,8,1] | 3 | — | — |

ReLU 明显最快，logistic 最慢——因为它在饱和区梯度太小。

### ③ 容量（螺旋 / 同心圆）

| 数据集 | 结构 | 准确率 | 轮数 |
|---|---|---|---|
| 螺旋 | [2,2,1] | 92.8% | — |
| 螺旋 | [2,8,1] | 97.8% | 28 |
| 螺旋 | [2,16,16,1] | 97.8% | 8 |
| 同心圆 | [2,4,1] | 71.3% | — |
| 同心圆 | [2,8,1] | 100% | 35 |
| 同心圆 | [2,8,8,1] | 100% | 16 |

### ④ 梯度消失：主要是**饱和型**激活的问题

在**随机初始化的 8 层网络**上量「首层/末层梯度范数比」：

| 激活 | 比值 |
|---|---|
| ReLU | **2.8**（几乎不衰减） |
| tanh | 0.58 |
| identity | 0.52 |
| logistic | **5.9e-7** |

原本的注释写的是"tanh / logistic 都明显衰减"，
实测 tanh 只有 0.58、根本不算明显，**logistic 才是灾难**（5.9e-7，差 6 个数量级）。
注释和页面文案都按实测改了。

> 注意这里必须在**随机初始化**的网络上量。
> 训练完之后 logistic 的比值会"回升"到 2.7e-2——因为网络已经把
> 大部分权重推到饱和区之外了，此时它不再是"梯度消失"的典型状态。

### ⑤ 学习率和数据尺度是耦合的（鸢尾花）

鸢尾花是**原始量纲**（萼片长 4.3~7.9，花瓣宽 0.1~2.5），
各维尺度差得远，学习率的容忍区间非常窄。每档跑 12 个种子：

| 学习率 | 成功种子数 | 平均准确率 |
|---|---|---|
| 0.01 | 12/12 | 97.1% |
| 0.05 | 12/12 | 96.0% |
| 0.1 | 10/12 | 93.1% |
| **0.2** | **0/12** | 52.8% |
| 0.3 ~ 1.0 | 0/12 | 33.3% |

**lr=0.2 是一道悬崖**；lr≥0.3 时准确率恒为 33.3% = ln3，
意思是**模型退化成"均匀猜三个类"**，完全没学到东西。

这就是为什么 `nnDatasets.ts` 里给每个数据集配了 `suggestedLr`
（xor/moons/circles/spiral 用 0.3，iris 用 0.1），
也是页面上那个"学习率 × 数据尺度"表格的来源。

## 6. ⚠️ 第二个坑：决策边界只画出两条横带

这个坑花的时间比算法本身还多。

**现象**：概率场只铺出底部一条彩色带，上面全白。

### 排查过程（三层，前两层是误判）

1. **以为是 `HeatmapChart` 没注册** → 改用 custom series。没解决。
2. **以为是 custom series 缺 `dimensions` / `encode`** → 补上。
   运行时确认 `encode={"x":0,"y":1}` 和 `dimensions=["x","y","w","h","p"]` 都写对了。
   还是没解决。
3. **以为是 `api.size()` 需要元数据** → 改成两个对角点各调一次 `api.coord` 相减。

### 真正的定位方法：不猜，直接量

把渲染器抽成独立模块（`src/dev/zzprobe.ts`），写一个 **Node 单元测试**
（`scripts/tests/zzprobe-renderer.mjs`，24 项断言）：

- 喂一份**假 api**（只有 `value` / `coord` 两个方法，把坐标轴映射成简单线性函数）
- 断言算出来的像素矩形是否等于手算值

这一步立刻抓到第一个真问题：**渲染器把 data 里的 2% 膨胀量丢掉了**。
data 里的宽度是 `cellW * 1.02`（故意让相邻格重叠，防止亚像素细缝连成"网格线"），
而我用固定的 `cellW` 去画，膨胀没了。改成从 `api.value(2)` / `api.value(3)` 读。

然后写第二个探测脚本，**直接问浏览器**：

- `chart.getZr().storage.getDisplayList()` → 5184 个 rect **全部存在**
- 逐个检查 `ignore` / `invisible` / 裁剪 / 父 group → **全部正常**
- 父 group 的 `boundingRect = {x:46.2, y:31.6, w:563, h:328.7}` → **正好覆盖整个绘图区**

几何、颜色、映射、可见性**全部正确**，但画面就是只有底部一条。

### 真正的原因：`progressive`

ECharts 对 custom series 默认启用**渐进渲染**（按 `progressiveThreshold` 分批建元素）。
分批创建的元素会被标记 `incremental`，走 `brushIncremental` 那条绘制分支，
结果只画出了第一批。

**验证**：只改 `GRID` 这一个数：

| GRID | 元素数 | 结果 |
|---|---|---|
| 40 | 1600 | ✅ 铺满 |
| 48 | 2304 | ✅ 铺满 |
| 56 | 3136 | ❌ 只铺底部一条 |
| 64 | 4096 | ❌ 只铺底部一条 |
| 72 | 5184 | ❌ 只铺底部一条 |

阈值在 48~56 之间，和"分批大小"的行为吻合。

### 修复

```ts
progressive: false,
```

一次性建完 5184 个纯色矩形，行为最确定。代价是首屏构建变慢了一点
（e2e 的 30s 超时因此顶到边界，把驱动器的超时提到 90s 并做成可配）。

**教训**：当"代码逻辑全对但渲染不对"时，别继续读源码猜，
应该**构造能直接读内部状态的最小观测**（这里是 `getDisplayList()`），
再用"只改一个变量"的对照实验去逼近阈值。

## 7. 第三个坑：滑杆的 120ms 防抖和重训竞态

页面给滑杆加了 120ms 防抖（拖动时不要每帧都重训）。e2e 里：

```js
setRange(slider, 0.3)   // 安排了一次 120ms 后的重训
nn().retrain()          // 立刻又重训一次
// → 两次重训打架，读到的是中间态（显示 93%，看似"没崩"）
```

修复：`setRange` 之后 sleep 700ms（> 120ms）再 `retrain()`。

另外 `setRange` 的助手一开始传的是 `.ctrl` 包装 div 而不是 `input[type=range]`，
`el.value = '0.3'` 对 div **静默无效且不报错**——这个也花了一整轮才定位。
