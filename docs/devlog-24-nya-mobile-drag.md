# devlog-24：修好「手机上拖 Nya 会变成滚页面」

> 2026-09-17。承接 `devlog-23` 第 9 节的诊断 —— 用户选了 **B 方案**（移动端也允许拖）。

## 1. 症状与根因（完整诊断见 devlog-23 §9）

手机上想挪 Nya：**她跟不动，页面却在上下滚**。

根因：`touch-action: none` **只写在 `@media (min-width: 641px)` 里**，
移动端她是 `manipulation` ⇒ 浏览器把这次触摸判成**滚动手势**并发出 `pointercancel`
⇒ 拖拽被 `endDrag()` 结束。而她身上的拖拽监听器**在移动端照样挂着**
（`pointerdown` 里只排除了 `if (open)`）。

实测（读 computed style）：

| | 桌面端 | 移动端 |
|---|---|---|
| 她的 `touch-action` | `none` | **`manipulation`** |

⇒ 这不是"手机上不可拖"的设计落地，而是**最差的一种组合**：
拖拽启动了、指针被捕获了、浏览器同时把这次触摸判成滚动。

## 2. 用户的选择与代价（明说过并接受）

三个候选：A 移动端真禁掉 / **B 也允许拖** / C 长按才算拖。

用户选 **B** —— 他的原话是"不能像在电脑上一样流畅移动nya"，要的就是"能拖"。

**代价**：她在手机上占的那一小块（右下角 **116×116**）**不能"起手就滚页面"**。
若以后觉得碍事，换成 C 是独立的一步，不用回头重做。

## 3. 改了什么（`src/styles/chat.css` 三处）

1. 基础规则 `touch-action: manipulation` → **`none`**
   （注释整段重写，把"为什么不能只在桌面端开"的完整机制写在代码旁边）；
2. **删掉** `@media (min-width: 641px)` 里那条重复的 `.nya-mascot { touch-action: none; }`
   —— 现在两端在基础规则里统一设，不再分桌面/移动；
3. 移动端那节注释：「手机上不再自由拖拽」→「**在手机上照样可以拖**」。

## 4. 回归防线

`scripts/tests/nya-panel.js` 新增一条：

```js
check('她身上接管了触摸手势（否则手机上拖动会被判成滚页面）',
      getComputedStyle(mascot).touchAction === 'none', ...)
```

两端都跑（`e2e:nya` / `e2e:nya:mobile`），断言数 **78 → 79**。

**反证做过**：把基础规则改回 `manipulation` ⇒ 两端都变 **78/79**，
红的正是这一条（实测值 `manipulation`）。恢复后 **79/79**。

## 5. 🔴 这个 bug 有一半「测不出来」

机制是**浏览器把触摸判成滚动手势并发出 `pointercancel`**，而 e2e 里派发的是
**合成的 `PointerEvent`** —— 合成事件**不触发浏览器默认行为**
⇒ **"页面在滚"这一半永远复现不了**（与 `pointer-capture` 那次是同一种盲区）。

所以：
- 断言能保住的是「`touch-action` 是 `none`」这个**必要条件**；
- **"手机上真的能拖了"必须真机验证** —— 手指是最可靠的验证。
