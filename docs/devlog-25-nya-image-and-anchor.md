# devlog-25：让 Nya 真的看见图，并且说准「图叫什么名字」

> 2026-09-18～09-20。两件事合并成一轮：
> ① 学生描述图里内容时她看不见（devlog-23 里那条"看不到图形"的约束是**当时的正确答案**，
> 现在需要**升级**而不是删除）；② `charts[].title` 用的**方位词**在窄屏上全错。

## 1. 用户报的原话

> 「nya 好像识图能力还是有点问题，你检查一下是怎么回事」（附了三张对话截图）

以及随后追加的要求：

> 「抓多张图也可以试下，成本不用管，怎么好怎么来」

## 2. 两个独立的缺口

### 缺口一：她的"眼睛"只有一条腿

devlog-23 定下的规则是**「你只能看到数字，看不到任何图形」**，
所以学生问"图里那条线是什么"时她只能说"我不确定，你找找看"。

这规则在**当时是对的**（她确实看不见，编了更糟），但它把「能指路」和「能看图」
一起否掉了。而用户的实际诉求是后者。

**修法**：把"眼睛"**分成两态**写：

| | 有图（本轮新增） | 没图（原来的行为） |
|---|---|---|
| 能说 | 形状、位置、疏密、覆盖范围 | 只有位置和名字 |
| 不能说 | **数字仍然只许引用状态值** | —— |

⚠️ **防幻觉那半一个字都没删，只是换了说法。** 直接照搬旧文案会让
她**对着图说"我看不到"** —— 那正是用户截图里的症状。

### 缺口二（更隐蔽）：指认图表用了**方位词**

`charts[].title` 当初是这么写的：

```
「页面上方那张大图」「下方左边那张小图」
```

这在**桌面布局**成立 —— `src/styles/layout.css` 里两张小图是左右并排。
但同一份 CSS 里有：

```css
@media (max-width: 768px) {
  .chart-row { grid-template-columns: 1fr; }   /* 变单列 */
}
```

⇒ **手机上两张小图是上下叠的，「下方左边那张」永远找不到。**

🔴 这是**只在窄屏暴露**的 bug，且**桌面端任何 e2e 都测不出来** ——
文案本身没错，错的是"文案假设了一个布局"。

**修法**：改用**页面上印着的 `.panel-title` 原文**做锚点。

- 跨设备成立（标题原文不随布局变）
- 学生能**逐字核对**（"页面上写着这行字吗"是可以判定的，"上方"不是）

## 3. 抓多张图

### 为什么不是"只抓主图"

`captureChartImage()` → **`captureChartImages(): Promise<string[]>`**

| 常量 | 值 | 作用 |
|---|---|---|
| `IMG_MAX_SIDE` | 900 | 单张最长边（压缩用） |
| `MAX_IMAGES` | 4 | 一次最多几张 |
| `IMG_TOTAL_CHARS` | 900_000 | 前端总量闸 |
| `MAX_TOTAL_BYTES` | 1_200_000 | 服务端总量闸（Vercel 请求体上限 4.5MB） |

**排序规则**：主图排第一（**面积最大**那张），其余按**文档顺序**
（用 `compareDocumentPosition`，因为"手机和桌面布局不同，但文档顺序是同一个"）。

**两条容易写错的**：

1. **同一帧**：先一次性拿完所有 `getDataURL()`，再统一压缩。
   不能"抓一张压一张"—— 图是动的，逐张抓会拼出不同时刻的画面。
2. **逐张独立失败**：某张压缩失败只丢那张，不整批弃用。

### 新旧字段兼容

新前端发 `images`（数组）**同时**发 `image`（单张老字段，镜像 `images[0]`）
⇒ 服务端必须**按 dataUrl 内容去重**，否则同一张图进两次、白烧 token。

⚠️ `images` 是**裸字符串数组**（`string[]`），不是 `{dataUrl}` 对象数组 ——
测试探针一开始按对象解，读出 `第一张前缀: null`。服务端 `normalizeImages()` 两种都认。

## 4. `check-orientation`：把这条约定焊死

新增 `scripts/check-orientation.mjs`，两条规则：

**规则 A —— 提示词里不许再有方位词**

```js
/(页面上方那张|下方左边那张|下方右边那张|页面下方那个|上方那张大图|下方那张小图)/
```

⚠️ **必须先剥注释再扫**。`nya.ts` 的注释里**故意留着**旧方位词
（解释"为什么不能这么写"），连注释一起扫会让这条检查**永远红着**。

**规则 B —— title 必须在页面 `.panel-title` 里逐字找到**

- 完全一致 ✅
- 前缀一致 ✅（页面标题更长时）
- `A / B` 形式 ✅（页面上两行字的合并写法）

**兜底口子：`anchor`**

页面上**真没印标题**的图允许写 `anchor:` 描述位置。
但必须在 `ALLOWED_ANCHORS` **白名单逐条点名**，白名单外的 `anchor` 判违规。

需要 anchor 的一共 5 条：

| 页 | 条目 |
|---|---|
| model-evaluation | `分数分布` / `交叉验证：每一折的准确率` / `判对了多少，判错了哪种` / `每一折长什么样` |
| decision-tree | `树结构` |

🔴 **这个白名单是反证逼出来的**：第一版没有它，
**随便编个 title + `anchor: '随便'` 就全绿** —— `anchor` 变成了免检通道。
（详见「四个'绿着但没验'的坑」第 2 条。）

## 5. 四个「绿着但没验」的坑

这轮最值钱的部分。**每个都是先写对了断言、再反证才发现它其实什么都没验。**

### 坑 1：改完源码没重新 build

`captureChartImages()` 一直返回空数组，而**所有测试全绿**。

根因：e2e 服务的是 `dist/`，改完源码不 `npm run build` 就测的是**旧产物**。
`catch` 里原本是安静 `return []` ⇒ 连报错都没有。

**修法**：① 重新构建；② `catch` 里加
`console.error('[nya] 抓图失败（这一轮她看不到图）：', err)`
—— **静默失败是这类 bug 的温床**。

### 坑 2：`anchor` 成了免检通道

反证做法：给某条编一个假 title + `anchor: '随便'` ⇒ **check:orientation 全绿**。

**修法**：`ALLOWED_ANCHORS` 白名单。
⇒ 教训：**凡是"写了某字段就跳过检查"的设计，都要立刻反问"那这个字段谁能写"。**

### 坑 3：页面内脚本不能用反引号和 `${}`

`scripts/e2e.mjs` 把被测脚本插进模板字符串：

```js
(async () => { ${body} })()
```

所以 body 里出现反引号会**提前闭合外层模板字符串**，报
`SyntaxError: Unexpected identifier '__chart'`。

⚠️ 我上一轮得出的"反引号和 `${}` 其实安全"**是错的** ——
只在 body **不含反引号**时成立。**页面内脚本一律字符串拼接。**

### 坑 4：「主图提到最前」这条逻辑**现有页面永远触发不到**

各页**面积最大的图恰好都排在文档第一** ⇒ 删掉这条排序逻辑，现有断言照样全绿。

**修法**：造**受控场景** —— 往页面插一个游离的假容器。

⚠️ 而造假容器时用了 `display: none` ⇒ **尺寸为 0** ⇒
「面积最大」退化成「取第一个」⇒ **还是假通过**。
必须用 `position: absolute; left: -99999px`（有尺寸、但不在视野里）。

⇒ 并给受控场景加**前提校验**（先断言"假容器确实是有尺寸的"）。

### 教训汇总

> **凡是"造分片 / 造受控输入"的测试，必须加前提校验，并反证它真能变红。**

同类踩坑史（散落在本项目多轮里）：
- Python `json.dumps` 算字节偏移 —— 它 `:` 后**带空格**，`JSON.stringify` 不带
  ⇒ 切点正落在字符边界 ⇒ 断言**永远是空的却不报错**。
- `anchor` 写成"写了就免检" ⇒ 假 title 也能全绿。

## 8. 遗留

- 各页 `.panel-title` 若有改动，`check:orientation` 会变红 —— 这是**预期行为**，
  改页面标题时要**同步改 `api/nya.ts` 里的 title**。这是刻意的耦合。
- `MAX_IMAGES = 4` 在 model-evaluation 那页（4 张图）正好够，
  若以后某页加到 5 张以上，需要重新评估总量闸。
