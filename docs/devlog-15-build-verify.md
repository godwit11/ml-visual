## 一、这篇要补的是什么

上一篇开发日志（14）在末尾留了一个明确标注的**未验证项**：

> `verify:all` 里的 e2e 步骤都走 `--serve`（需要 `dist/`），而 `npm run build` 会清空 `dist/`，
> 在本机沙箱里被安全护栏拦过，**没有重试**。所以两个 bug 修复是用 dev server 验证的（功能等价），
> 生产构建本地没跑过。

这次把这个口子补上。核心问题不是"再跑一遍命令"，而是**为什么会被拦、怎么绕过、以及补验之后结论的含金量发生了什么变化**。

## 二、为什么 `npm run build` 会被安全护栏拦截

这不是权限配错，也不是随机故障。原因是构建的第一步：

```
vite build
  → 清空 dist/ 目录
  → 重新写入产物
```

**清空目录属于破坏性文件操作。** 安全护栏不区分"这个 `dist/` 是可随时重建的构建产物"还是"用户的重要文件"，一律要求人工确认。上次误点拒绝，命令就中止了 —— 护栏在正常工作，不是 bug。

### 执行顺序上的一个设计

这次刻意把顺序拆成两步：

| 步骤 | 命令 | 是否触碰 dist | 目的 |
|---|---|---|---|
| 1 | `npm run typecheck` | 否（纯读源码） | 先拿到类型检查结果，不触发护栏 |
| 2 | `npm run build` | **是**（清空重建） | 需要用户确认 |

**为什么这么排**：如果先跑 `build` 被拦，前面什么都拿不到；先跑 `typecheck` 能确保即使构建失败，也有一份可用的验证结果，不白跑一轮。

## 四、关键认识：补验之后，回归的含金量变了

这是本篇最重要的一点，也是当初那个"未验证项"真正的影响所在。

```
npm run verify:all   →   28/28 步通过，耗时 235.1s，首页断言数 327 一致
```

**为什么这次和上次不一样：**

`verify:all` 的 e2e 步骤是通过 `vite preview` 起本地服务的。而 **`vite preview` 喂给浏览器的文件，正是 `dist/` 里的内容**。

- 之前：`dist/` 是旧的或空的 → 这些步骤相当于在做"dev server 功能等价"的**替代验证**，不等于产物验证。
- 现在：`dist/` 是刚构建出的新产物 → **这 28 步是真的跑在构建产物上的**。

同一套命令、同样的断言数，但验证的对象完全不同。这就是补验的价值 —— 不是"多跑了一遍"，而是**从"验证源码"变成了"验证交付物"**。

### 28 步覆盖了什么

| 分组 | 内容 |
|---|---|
| 静态检查 | `tsc --noEmit`、渲染器单元测试、head 标签一致性 |
| 页面质检 | 桌面 + 移动各 8 项（资源加载 / 横向溢出 / 图表尺寸 / 内容非空等） |
| 功能 e2e | 首页 + 10 个演示页（14~66 条断言不等） |
| 链接可达性 | 首页 11 条 + 演示页 3 条 |
| 算法对拍 | 十套，全部与 sklearn 严格比对 |

汇总：**11 页功能断言全绿、十套对拍全过、0 个 JS 异常。**

## 五、一处必须说明的差异

本地的 `npm run build` **不包含** `gen-sitemap.mjs` 这一步。

那一步写在 `vercel.json` 里：

```json
{
  "buildCommand": "node scripts/gen-sitemap.mjs && npm run build",
  "outputDirectory": "dist"
}
```

也就是说 **Vercel 的构建流程 = 生成 sitemap + `npm run build`**，而本地只跑了后半段。

`dist/sitemap.xml` 确实存在，但那是上一轮 Vercel 构建遗留在本地的产物，**不是这次生成的**。所以严格讲，本地产物与 Vercel 产物在这一处有差异。不影响任何页面渲染，但如果要本地完整复现线上流程，应执行：

```bash
node scripts/gen-sitemap.mjs && npm run build
```

## 七、可复用的经验

1. **构建验证要拆步**：先跑只读检查（`tsc`），再跑破坏性步骤（`vite build`），避免被拦后一无所获。
2. **"用 dev server 验证"和"用 dist 验证"不是一回事**：前者验源码，后者验交付物。
   当验证工具链支持 `--serve`（读构建产物）时，务必让 `dist/` 处于最新状态再跑回归。
3. **破坏性操作被拦先想清楚原因**，别当成权限故障去折腾配置 —— 多半是护栏在正确工作，需要的是人工确认。
